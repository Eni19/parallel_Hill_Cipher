Capítulo 1 • O Problema

Por que inventaram a Cifra de Hill?

Durante séculos, as pessoas usavam cifras como a Cifra de César: trocavam cada letra individualmente por outra fixa (exemplo: todo A virava D).

❌ O Defeito das Cifras Antigas

Em português ou inglês, a letra 'A' e a letra 'E' aparecem o tempo todo. Se você sempre troca a letra 'A' por 'X', um espião só precisa contar qual letra mais aparece no texto cifrado e descobre sua mensagem em minutos! Isso se chama análise de frequência.

💡 A Solução de Lester S. Hill (1929)

Em 1929, o matemático Lester Hill teve uma ideia genial: "E se nós não trocássemos letra por letra, mas sim blocos de letras juntos (pares ou trios de letras) usando matemática?"

Com a Cifra de Hill, a mesma letra A pode virar X na primeira palavra e virar M na segunda palavra, porque o resultado depende das letras vizinhas dela no bloco! A análise de frequência simples fica completamente inútil.

Como Desfazer a Mistura: A Matriz Inversa (K⁻¹)

Para encriptar, multiplicamos o texto pela Matriz Chave K. Para decifrar, precisamos fazer o caminho inverso: multiplicar o texto cifrado pela Matriz Inversa K⁻¹.
Mas aqui surge um grande desafio matemático que o código em C de Tanay PrabhuDesai resolve de forma brilhante e simples!

O Grande Desafio

1. Por que não podemos simplesmente "dividir" matrizes em Criptografia?

Na álgebra linear comum do colégio, a inversa de uma matriz é calculada por:
K⁻¹ = (1 / Determinante) × Matriz Adjunta

❌ O Problema da Fração

Imagine que o determinante da chave seja 25 e um elemento da matriz adjunta seja 8.
Se fizermos a divisão comum: 8 / 25 = 0.32.
Em criptografia isso não existe! Não existe a letra de número 0.32 no alfabeto. Todas as letras precisam ser números inteiros de 0 a 25.

💡 A Sacada do Relógio (+26)

Lembre-se do nosso relógio de 26 horas:
Dar uma volta completa no relógio (somar +26) cai exatamente na mesma hora!
Em termos matemáticos: 26 ≡ 0 (mod 26).
Então, podemos somar 26 quantas vezes quisermos sem alterar o valor da letra!

O Truque em C

2. Como a função Mat_add_num_till_divisible Resolve Isso

Em vez de usar fórmulas complicadas de teoria dos números (como o Algoritmo Estendido de Euclides), o código de referência em C (tanayseven_hill_cipher.c) faz uma busca direta:

A Lógica em Português Claro:

  1. Pega cada número da matriz adjunta.
  2. Pergunta: "Esse número é divisível pelo determinante sem sobrar resto?"
  3. Se não for, soma +26 a ele!
  4. Pergunta de novo: "Agora é divisível?" Se não for, soma +26 de novo!
  5. Assim que o número se torna um múltiplo perfeito do determinante, divide pelo determinante!
  6. O resultado da divisão é um número inteiro perfeito, sem casas decimais e sem aproximações!

Veja o trecho real em linguagem C que faz exatamente isso:

tanayseven_hill_cipher.c (linhas 214-222) Função Mat_add_num_till_divisible
void Mat_add_num_till_divisible(Matrix mat, float num, float divisor) { for (int r = 0; r < mat.rows; ++r) { for (int c = 0; c < mat.columns; ++c) { // Enquanto o número não for divisível pelo determinante, soma 26! while ((int)Mat_get_element(mat, r, c) % (int)divisor) { Mat_set_element(mat, r, c, Mat_get_element(mat, r, c) + num); } } } }

3. As 4 Etapas para Construir a Chave Inversa (K⁻¹)

Etapa A • O Determinante

Calcula o determinante da matriz chave $K$ e aplica módulo 26.
Exemplo: se $\det = 441$, no relógio $441 \pmod{26} = \mathbf{25}$.

Etapa B • Menores e Cofatores

Para cada célula, elimina a linha e coluna e calcula o minideterminante que sobra, alternando os sinais (+ e -).

Etapa C • Matriz Adjunta

Gira a matriz de cofatores: o que era linha vira coluna (transposição).

Etapa D • Ajuste com +26 e Divisão

Aplica a função em C somando 26 até ser divisível por $\det$, divide por $\det$ e aplica mod 26.

O que acontece com a imagem?

Pense na imagem como uma lista de números. O programa combina esses números usando uma matriz; para recuperar a imagem, aplica a mesma matriz uma segunda vez.

1

Um pixel vira números

Em uma imagem colorida, cada pixel tem três canais: vermelho, verde e azul. Cada canal vai de 0 a 255. Por exemplo, (255, 0, 0) é vermelho. Uma imagem cinza PGM usa um número por pixel.

R 255G 0B 0
2

Quatro bytes formam um bloco

O programa lê quatro valores seguidos dos canais e os coloca em uma coluna de números chamada vetor, como P = [12, 90, 200, 35]. O bloco pode atravessar a fronteira entre pixels. No fim, grupos menores também são tratados sem perder bytes.

129020035→ bloco P
3

A semente monta a chave

A semente é o número que você digita. Ela e a posição do bloco geram uma tabela de números 2 × 2, chamada matriz A. Uma regra fixa monta a matriz 4 × 4 K. A mesma semente e a mesma posição sempre geram a mesma K.

4

A matriz transforma o bloco

Cada uma das quatro linhas de K multiplica os quatro valores de P e soma os produtos. Fica apenas o resto da divisão por 256. Assim, todo valor volta à faixa de 0 a 255: 300 mod 256 = 44.

300− 256= 44
5

A mesma operação recupera

A chave foi construída para que K × K = I. I é a matriz identidade: multiplicar por ela deixa os números como estavam. Por isso, K × (K × P) = P. É preciso usar a mesma semente.

6

As threads dividem o serviço

Um bloco não precisa esperar pelo outro. Cada thread recebe um intervalo de blocos, calcula seus resultados e escreve em posições distintas. Depois que todas terminam, a imagem de saída está completa.

Antes de rodar

O que muda entre seq, omp e pipeline?

Os três modos fazem as mesmas três etapas com cada quadro: ler (receber o quadro do FFmpeg), cifrar e gravar. O resultado cifrado é idêntico nos três. O que muda é quem faz cada etapa e quando.

Desenho esquemático com 3 quadros: ler e gravar valem 1 unidade de tempo e cifrar vale 3 unidades com uma thread. Ele mostra o caso ideal. Na prática o ganho é menor, porque as threads disputam os núcleos com o FFmpeg (veja o benchmark abaixo).

seq

Uma única thread lê, cifra e grava, um quadro depois do outro. É a base de comparação.

omp (parallel for)

Só a cifra é dividida: #pragma omp parallel for reparte os blocos de cada quadro entre as N threads. Ler e gravar continuam com uma thread só; enquanto isso, as outras ficam esperando.

pipeline (linha de montagem)

Cada thread tem uma função fixa: uma só lê, uma só grava e N só cifram. Enquanto o quadro 1 é cifrado, o quadro 2 já está sendo lido e o 0 está sendo gravado. Três buffers se revezam, e uma barreira separa cada passo.

O que significa “3+2”?

O número escolhido é sempre o de threads de cifra. O pipeline acrescenta +2 threads de entrada e saída (uma leitora e uma gravadora). Assim, pipeline 3+2 cria 5 threads.
